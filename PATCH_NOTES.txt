LocalMangaTranslator - 누적 패치 노트 / 작업 인수인계
============================================================

문서 목적
------------------------------------------------------------
이 파일은 LocalMangaTranslator의 장기 작업 기록과 다음 채팅/작업 세션 인수인계를 위한
누적 패치 노트다.

앞으로 새 버전을 작업할 때마다 이 파일 하나에 버전 번호를 추가하고,
아래 항목을 가능한 한 상세히 기록한다.

- 왜 수정했는가
- 실제로 어떤 문제가 관찰되었는가
- 원인을 어떻게 판단했는가
- 어떤 코드/파이프라인을 변경했는가
- 무엇은 의도적으로 변경하지 않았는가
- 어떤 디버그 파일/audit 필드가 추가되었는가
- 어떤 테스트로 회귀를 잠갔는가
- 실제 이미지 테스트 결과는 어땠는가
- 아직 남은 문제와 다음 우선순위는 무엇인가

새 채팅에서 작업을 이어갈 때는 이 파일, PIPELINE_V2.md,
docs/PIPELINE_REFACTOR.md를 먼저 읽으면 현재 상태를 빠르게 복원할 수 있다.


프로젝트
------------------------------------------------------------
프로젝트명: LocalMangaTranslator
GitHub: https://github.com/jejuzipsa/LocalMangaTranslator
주 작업 브랜치: rewrite/pipeline-v2

목표:
Windows용 로컬 만화 이미지 번역기.
OCR -> Vision OCR 검수 -> 번역 -> 말풍선/캡션 검출 -> 원문 삭제 ->
배경복원 -> 검수 -> 한국어 조판까지 자동 처리한다.

현재 개발 우선순위:
번역 문장 품질 자체보다 이미지 처리 파이프라인의 정확도와 안전성이 우선이다.
특히 OCR/검출 -> 원문 삭제 -> 배경복원 -> 검수 -> 조판의 구조적 안정성을 먼저 확보한다.


핵심 불변 원칙
------------------------------------------------------------
1. RT-DETR Bubble / TextBubble / TextFree geometry는 immutable evidence로 취급한다.
2. OCR/번역/후처리는 RT-DETR이 만든 erase geometry를 이동하거나 새로 만들지 않는다.
3. OCR output은 observation이지 authority가 아니다.
4. Translation approval과 erase approval은 같은 의미가 아니다.
5. 잘 지운 원문을 검수 오판으로 다시 살리지 않는다.
6. Layout 실패 또는 erase 검수 실패 시 해당 unit은 원본 픽셀을 보존한다.
7. erase + typeset은 atomic commit으로 묶는다.
8. 글자를 단순히 지우는 것보다 글자 뒤에 원래 있어야 할 배경을 복원하는 것이 핵심이다.
9. Flat Bubble/Caption과 Artwork/복잡 배경은 복원 전략을 분리한다.
10. 일반 대사/캡션 안정성을 깨면서 stylized text 하나에 과적합하지 않는다.
11. RapidOCR 영역진단 및 보조 OCR evidence는 계속 유지한다.
12. 애매한 경우에는 artwork 손상보다 원본 보존을 우선한다.
13. 디버그/audit 결과가 실제 최종 commit 상태와 분리되지 않도록 한다.


============================================================
이전 작업 요약 - 0001 ~ 0018
============================================================

초기 문제
------------------------------------------------------------
초기 테스트에서는 다음 문제가 반복되었다.

- OCR이 말풍선 전체를 놓치면 번역/erase 자체가 시작되지 않음.
- OCR이 artwork를 text로 오인하면 잘못된 erase 후보로 전파될 수 있음.
- Vision OCR 보정이 주변 대사를 빌려오거나 지나치게 확장할 수 있음.
- OCR line geometry와 erase geometry가 너무 밀접하게 결합되어 있었음.
- 하나의 실제 말풍선이 여러 OCR fragment/unit로 쪼개지거나,
  반대로 먼 문장들이 하나의 unit으로 합쳐지는 문제가 있었음.

리팩터링 방향
------------------------------------------------------------
파이프라인을 다음 evidence stage로 분리하는 방향을 확정했다.

Page analysis
-> page-wide container candidate detection
-> candidate validation
-> global/focus/container OCR
-> OCR observation merge
-> line validation
-> line-to-container ownership
-> reading order
-> translation unit creation
-> Vision OCR review
-> final translation
-> erase decision
-> layout planning
-> erase/inpaint
-> typeset
-> post-render validation

핵심 구조 변화
------------------------------------------------------------
- OCR observation을 pass별로 보존.
- page-wide container candidate를 OCR seed 없이 생성.
- container 1x/2x OCR을 도입하고 cross-scale agreement를 evidence로 사용.
- line ownership을 explicit하게 기록.
- one canonical line = one active owner 원칙 도입.
- ambiguous/weak ownership은 강제로 배정하지 않고 orphan 또는 held 상태로 둠.
- container-first grouping과 legacy fallback grouping을 분리.
- Vision correction은 번역 보조이지만 erase 권한을 직접 주지 않음.
- 실제 detector/safe-mask 근거가 없는 fallback rectangle은 erase 권한을 주지 않음.
- short/low-confidence OCR fragment가 Vision에서 긴 문장으로 과도하게 확장되는 경우 차단.
- lossless WebP 기반 결과/디버그 출력 구조를 정리.

관련 설계 문서:
- docs/PIPELINE_REFACTOR.md
- ARCHITECTURE.md
- docs/ARCHITECTURE_2.md

0019 - Atomic erase + typeset commit
============================================================

문제
------------------------------------------------------------
erase는 성공했지만 layout/typeset이 실패하거나,
반대로 검수 실패가 뒤늦게 발생하면 말풍선이 빈 채로 남는 문제가 있었다.

변경
------------------------------------------------------------
- TextBubble이 source-text pixel과 erase review를 소유.
- 이미 연결된 parent Bubble이 layout/font fitting을 소유.
- layout validation을 erase보다 먼저 수행.
- erase review까지 통과한 unit만 committed cleaned image에 복사.
- binding/layout/mask/residual review 중 하나라도 실패하면
  해당 unit은 원본 픽셀을 유지하고 한국어 overlay도 하지 않음.
- v2_05_committed_cleaned.webp를 원본 + 승인된 TextBubble edit만으로 구성.
- v2_commit_audit.json에 각 requested unit을
  translated 또는 original_preserved:* 상태로 기록.

핵심 invariant
------------------------------------------------------------
EraseCommittedUnits == TypesetCommittedUnits

추가 안정화
------------------------------------------------------------
OCR line consolidation에서 confidence가 비슷하면 더 완전한 line을 우선하도록 하여
THE MIDDLE 같은 fragment가
YOU'RE STILL IN THE MIDDLE 같은 완전 문장을 덮어쓰지 않도록 함.


============================================================
0020 - TextFree / colored glyph / 4-stage audit
============================================================

관찰된 문제
------------------------------------------------------------
1. RT-DETR TextFree detection이 region analysis에는 있지만 V2 immutable target에는 빠짐.
2. 빨간 NONONO 같은 colored lettering이 grayscale residual review를 통과해 남을 수 있음.
3. 완료검토가 ORIGINAL | FINAL | DIFF뿐이라 erase 단계 문제와 typeset 문제를 구분하기 어려움.

변경
------------------------------------------------------------
- V2DetectionSnapshot에 TextBubble + TextFree를 모두 포함.
- TextBubble은 parent Bubble을 layout anchor로 유지.
- TextFree는 parent Bubble을 새로 만들지 않고 detector rect 자체를 conservative anchor로 사용.
- colored glyph rescue에서 chroma-contrast component를 제한적으로 추가.
- final audit를 가능한 경우 4단계로 변경:
  1 ORIGINAL
  2 ERASE COMMIT
  3 FINAL
  4 DIFF
- audit summary에 preserve reason을 기록.

의도
------------------------------------------------------------
erase와 typeset failure를 분리해 볼 수 있게 하고,
color text를 grayscale-only assumption에서 벗어나 처리.

============================================================
0023 - Best-pass erase + translation safety
============================================================

문제
------------------------------------------------------------
retry가 항상 first pass보다 낫지 않은데도 retry 결과를 최종으로 쓰는 경우가 있었음.

변경
------------------------------------------------------------
- retry는 optional candidate로 취급.
- first-pass와 retry residual score를 target별 비교.
- retry가 나쁘면 해당 footprint만 first-pass cleaned image에서 복구.
- SelectedResidualPixels / SelectedPass audit 추가.

번역 safety gate
------------------------------------------------------------
- punctuation/noise-only corrected text는 translator로 보내지 않음.
- placeholder/template response reject + 1회 repair.
- NOT/CAN'T/DON'T/WON'T/NEVER 같은 영어 negation이 한국어 negation cue를 잃으면 retry.
- final result와 Vision draft 모두 실패하면 원본 보존.


============================================================
0024 - Residual review correction
============================================================

관찰된 문제
------------------------------------------------------------
실제 cleaned image는 이미 비어 있는데,
reviewer가 inpaint texture나 주변 contrast를 다시 text처럼 잡아서
atomic commit이 영어 원문을 되살리는 false-positive가 발생.

변경
------------------------------------------------------------
- 7x7 local review halo 복원.
- raw residual과 effective residual 분리.
- original erase mask 안의 재-segmented pixel은 surviving source text로 보지 않음.
- retry는 immutable glyph mask 밖의 suspicious residual을 중심으로 판단.
- raw residual은 sanity bound로 유지.
- best-pass selection 유지.
- raw/effective residual before/after retry를 audit에 기록.

============================================================

문제
------------------------------------------------------------

------------------------------------------------------------
Translation context와 physical commit ownership을 분리한다.

문맥은 여러 말풍선을 함께 참조할 수 있지만,
erase / layout / review / rollback은 immutable detector owner별로 독립해야 한다.

Hard rule:
- 서로 다른 RT-DETR TextRegion owner는 하나의 physical commit unit이 될 수 없음.
- TextBubble과 TextFree는 geometry fallback에서 같이 묶지 않음.
- 서로 다른 parent Bubble은 하나의 commit unit으로 묶지 않음.
- 같은 candidate rectangle만으로 두 TextRegion을 합치지 않음.
- rejected candidate가 valid duplicate candidate를 미리 제거하지 못함.

0034는 "서로 다른 detector owner를 한 commit unit에 묶지 않는다"는

-> legacy CandidateId
-> candidate.RegionId
-> candidate 영역 안에서 TextBubble 탐색

문제:

0035 핵심 원칙
------------------------------------------------------------
Detector TextRegion이 ownership의 최종 authority다.

새 순서:
OCR block geometry
-> RT-DETR TextBubble 직접 매칭
-> TextBubble의 parent Bubble 결정
-> 그 parent Bubble에 대응하는 candidate를 역으로 선택
-> RegionId / RegionContainer / RegionTextRegion 갱신
-> UnitOwnership CandidateId와 LineOwnership도 detector owner 기준으로 교정

즉 ContainerCandidate는 더 이상 physical owner를 결정하지 않는다.
candidate는 detector owner가 정해진 뒤 mask/layout/OCR evidence를 제공하는
보조 자료로만 사용한다.

- 실제 TextRegionId
- UNBOUND

중요:
Laya가 geometry를 만들 수 없다.
선택 가능한 owner는 RT-DETR이 이미 검출한 immutable TextBubble뿐이다.


2. detector_retry
Classic 기준 UNBOUND이고,
주변에 안전한 RT-DETR TextBubble 후보가 없는 OCR unit에 대해
다른 detector scale 재검사가 필요한지 noul(true/false)로 판정.

이 판단 역시 geometry 생성 권한이 없다.
후속 multi-scale detector 실험을 위한 triage signal만 기록한다.

page014 NONONO처럼:
- OCR은 강하게 존재
- 번역도 가능
- RT-DETR target 자체는 사라짐
인 케이스가 이 로그의 주요 대상이다.


3. render_recovery
Vision이 dialogue/thought/caption을 Render=false로 반환한 경우,
detector/OCR evidence를 바탕으로 재활성화할지 Laya가 별도 판정.

Classic의
PagePipelineService.ShouldRecoverDetectorOwnedRenderableUnit()
결과와 비교해 Match/Mismatch 기록.

page021
"I DON'T KNOW ANYMORE. I DON'T--"
같은 케이스가 주요 대상이다.


4. duplicate
같은 physical Bubble RegionId 아래에 여러 번역 candidate가 존재할 경우,
어떤 candidate를 살릴지 Laya choice로 판정.

Classic winner:
RenderPipelineService의 실제 V2CandidateKeepScore 기준.

Laya evidence:
- source/corrected text
- secondary OCR agreement
- OCR confidence
- detector TextRegion link

page032 "AM I RIGHT?" 약한/강한 후보,
page012 혼합 OCR 잔재 같은 케이스 비교 목적.


Shadow log
------------------------------------------------------------
각 페이지 debug 폴더에 추가:

- <page>.laya_decisions.json
- <page>.laya_summary.json

laya_decisions.json:
- Schema = pipeline-v2-laya-shadow-v1
- SourceFile
- Track
- Mode
- Runtime
- Available
- Error
- Decisions

각 decision:
- Kind
- RegionId
- RuleDecision
- LayaDecision
- Confidence
- Match
- Status
- Evidence

Shadow에서는 항상 Status=shadow_only이며
LayaDecision은 실제 pipeline action에 반영하지 않는다.


laya_summary.json:
- Schema = pipeline-v2-laya-summary-v1
- TotalDecisions
- Matched
- Mismatched
- NoAnswer
- ByKind
  - Compared
  - Matched
  - Mismatched
  - NoAnswer
  - MeanConfidence
